# 云存储 · 操作手册

> **给谁看**：要把平台的图片 / 附件从「服务器本地」搬到云厂商对象存储的管理员。
> 全文按**界面上实际点的位置**写：点哪里 → 页面上做什么 → 系统会发生什么。
> 这是**一次性配置、长期不用管**的模块，配好之后基本只用「文件浏览」和「健康检查」。

---

## 一、这个模块解决什么问题

平台上的图片、附件原来都存在**服务器本机的 MinIO**（一套自建的小对象存储）。文件一多，本机硬盘就是瓶颈，外网访问也慢。云存储应用就是来**换后端的**：文件存到云厂商的对象存储，本机 MinIO 转为「备份」角色。

支持四家（另有内置 MinIO，见下）：

| provider | 名字 | 协议 |
|---|---|---|
| `tencent` | **腾讯云 COS** | S3 兼容 |
| `aliyun` | **阿里云 OSS** | S3 兼容 |
| `qiniu` | **七牛云 Kodo** | S3 兼容（必须 path-style） |
| `upyun` | **又拍云** | 又拍自己的 REST API |

> **内置的 MinIO 不在界面可选列表里** —— 它只作为「迁移的源」使用，负责把老 MinIO 上的文件搬到新云存储。

**换完之后谁在用？** 平台上所有要传文件的地方都会走这里，最典型的是 **CMS 的媒体库**：你在媒体库传的图，实际就落在「当前激活」的这家云存储里。

---

## 二、从哪儿进

后台左侧菜单 → **云存储**（☁️），**单一入口**，没有子菜单。整页从上到下六个区块：

| 区块 | 干什么 |
|---|---|
| **当前激活** | 选「现在用哪家」，下拉里标了 ✓ / (未配置) |
| **通用设置** | 「保留本地备份 (MinIO)」开关 |
| **各 provider 标签页** | 逐个配凭据：填、保存、测试连接、编辑、删除 |
| **健康检查** | 一键检查所有 provider 通不通 |
| **文件浏览** | 按桶 + 前缀列文件，复制外链、删除 |
| **迁移：MinIO → 当前 provider** | 把老 MinIO 的存量文件搬过来 |

> **看不到这个菜单 = 没有权限**，对着第六节《权限对照表》找管理员加。

## 三、十分钟接入七牛云

以七牛云为例；腾讯 / 阿里同理，只是 Region / Endpoint 不一样。

**第 1 步 · 先在云厂商那边准备好。** ① 建一个**存储桶 / 空间**，记下桶名；② 建一对**密钥**（AccessKey / SecretKey），给对象存储读写权限；③ 如果要做**图片直链**（官网图片直接显示），绑一个 **CDN 域名**并记下来。

**第 2 步 · 填凭据。** 在页面中间的标签栏点 **七牛云 Kodo**，填这 7 个格子：

| 字段 | 必填 | 说明 |
|---|---|---|
| **AccessKey / Operator** | ✅ | 七牛的 AccessKey |
| **SecretKey / Password** | ✅ | 七牛的 SecretKey |
| **Bucket 名称** | ✅ | 你建的那个空间名 |
| **Region** | 选填 | 七牛填 `z0` / `z1` / `z2` / `cn-east-2` |
| **Endpoint** | ✅（又拍云除外） | 七牛固定格式 `https://s3-<region>.qiniucs.com` |
| **CDN 域名** | 选填 | 填了以后生成的公网图片地址优先用这个域名 |
| **路径前缀** | 选填 | 想给文件统一加一层目录前缀时用 |

点 **保存凭据**：**AccessKey / SecretKey / Bucket 三项必填**（缺一个会弹提示）、**Endpoint 必填**（又拍云不用填）；成功后弹「已保存」，标签页上出现一个**绿点 ●**，表示这家配好了。

> 🔒 **密钥是加密存储的**，配好以后页面上只显示打码值（如 `AccessKey: xxx****`），不会明文回显。想改就点 **编辑凭据**，**SecretKey 留空表示保留原来的**。

**第 3 步 · 测一下通不通。** 同一块区域点 **测试连接**：✓ **连接成功**说明密钥、桶、Endpoint 都能访问；✗ 会跟一条错误信息，照着改（最常见是 Endpoint 写错，比如七牛少了 `s3-`，或桶名不对）。页面上「**健康检查**」区块的 **检查所有 provider** 会把四家一起查一遍，逐家 ✓ / ✗ 并给出原因。

**第 4 步 · 切成「当前激活」。** 回到最上面 **当前激活** 区块，下拉切到 **七牛云 Kodo**（已配置的带 ✓）。⚠️ 前置条件：**必须先在标签页里把凭据配好并保存**，否则会报「该 provider 尚未配置凭据」。切换成功后，**之后所有上传都会落到七牛云**（切之前已传的文件还在原处，需要就用下面的迁移功能搬）。

**第 5 步 · 验证。** 去 **CMS → 媒体库** 传一张图：图能传上去、能看到缩略图；点开详情 **复制 URL**，粘到浏览器能打开 —— 说明公网访问路径也通了。到这里切换就算完成。

## 四、日常操作速查

**通用设置** —— 只有一个开关 **保留本地备份 (MinIO)**，**默认开**：开启后上传到云存储的文件会**同时在本地 MinIO 留一份副本**，服务器本机还占硬盘，但换了云厂商也不怕旧文件丢。改完点 **保存设置**。

**上传文件走哪里？** ⚠️ **这个页面不提供上传入口**。上传发生在用文件的地方 —— 日常最常用的是 **CMS → 媒体库**（点或拖，支持多选）。你只要保证「当前激活」的那家凭据是对的，那个地方传的东西就会自动落到它的桶里；**上传时不需要选桶**，系统用当前激活凭据里的 Bucket。

**看文件、拿链接、预览** —— 云存储页面只给「列表 + 操作」，**不提供在线预览**；要肉眼确认图片，去 **CMS → 媒体库**（那里有缩略图和详情侧栏）。在这个页面：

1. 填 **Bucket**（一般默认就填好当前激活的桶了）和 **prefix**（可选，按目录前缀过滤）；
2. 点 **列出**，得到一张表：**Key（文件路径）/ 大小 / 修改时间 / 操作**；
3. 每行两个动作：

| 动作 | 说明 |
|---|---|
| **复制外链** | 生成一个**带签名的临时地址**并自动复制到剪贴板（有效期 **1 小时**，过期要重新复制）。粘到浏览器就能预览或下载。⚠️ 这个链接**谁拿到谁能打开**，别往公开群里发 |
| **删除** | 二次确认后**从云存储里直接删掉**，**不可恢复**。删前确认没有页面在引用它 |

> 一次最多列 **100 个**（上限 1000）。文件多时用 **prefix** 缩小范围，例如只列 `2026/06/` 下面的。

**健康检查** —— 想确认「现在到底哪家能用」时点 **检查所有 provider**，它会逐家尝试访问，未配置凭据的直接标「未配置凭据」。换密钥、改桶名之后，第一件事就是点一次健康检查。

**迁移：MinIO → 当前 provider** —— 用于把老 MinIO 上的存量文件搬到新云存储：

1. 先在「当前激活」里切到目标云存储（且已配好凭据）；
2. 在 **迁移** 区块填 **源 Bucket** 和 **prefix**（可选，只搬某个目录）；
3. 点 **开始迁移** → 二次确认「迁移会比较耗时，是否继续？」；
4. 页面每 2 秒刷新一次进度，状态依次是：`pending` / `running` 进行中（显示「已完成 / 总数 (失败 N)」）、`done` 全部搬完、`partial` 搬完但部分失败、`failed` 整体失败（后两种都会给出错误信息）。

> ⚠️ **迁移不会删源文件**，搬完确认无误后源 MinIO 里的东西由管理员另行清理。⚠️ 迁移期间**别切换「当前激活」**，会走乱。

## 五、进阶：私有桶与公开桶

这个应用**本身没有「公开 / 私有」开关** —— 桶是公开还是私有，取决于你在**云厂商控制台**给这个桶设的读权限。但两者使用方式差别很大：

| | 公开桶 | 私有桶 |
|---|---|---|
| 直接拼地址（`Endpoint/桶/文件` 或 CDN 域名 + 文件路径） | 能打开 | **打不开**，返回拒绝访问 |
| 能否用在官网 / 对外页面上 | 能，图片直链可用 | 不能直接用，得走签名地址 |
| 怎么拿能用的地址 | 直接用 CMS 媒体库里那个**永久 URL** | 只能在**文件浏览**里点 **复制外链** 生成签名地址 |
| 签名地址有效期 | —— | **1 小时**，过期需重新生成 |

实践建议：**对外展示的图**（官网、产品图、案例图、新闻封面）用**公开桶**，最好再挂 CDN 域名，访问快、地址稳定；**内部单据、合同、导出文件**用**私有桶**，靠「复制外链」临时分享；页面上的图片建议走域名而不是 IP，这样换云存储时只改配置，不用改页面。

## 六、权限对照表

云存储的权限分三档，比一般应用细：

| 权限 | 能做什么 |
|---|---|
| `cloud_storage:read` | 看配置页面（密钥打码）、**健康检查**、**文件浏览列表**、查询迁移任务进度 |
| `cloud_storage:write` | **删除文件**、**生成外链**（预签名地址） |
| `cloud_storage:admin` | **保存 / 删除凭据**、**切换当前激活**、改「保留本地备份」设置、**启动迁移** |

> ⚠️ 三档别合并给同一个人：「看一眼文件列表」只需要 `read`，「删文件 / 拿外链」要 `write`，而**碰密钥、换存储厂商是 `admin`** —— 改了激活 provider 等于换了全平台的文件出口，尤其别发给只做日常运营的人。

**建议分法**：**只查文件** 给 `cloud_storage:read`；**运营 / 内容同事** 给 `read` + `write`（能删图、能拿外链）；**运维负责人** 三档全给，只给 1～2 个人。

## 七、常见问题

- **Q：为什么下拉里只有腾讯 / 阿里 / 七牛 / 又拍，没有 MinIO？** MinIO 是**内置的本地存储**，不作为界面上的 provider 供选择，只作为「迁移的源」。没装云存储应用、或没配任何云存储凭据时，平台会自动回退到本机 MinIO —— 先让它能用，不至于传不了文件。
- **Q：切「当前激活」时报「该 provider 尚未配置凭据」？** 先把那个 provider 的标签页填好并**保存凭据**（保存后标签上会出绿点），再回来切。
- **Q：七牛云连接失败，报错看不懂？** 九成是 **Endpoint** 和 **Region**。七牛的 S3 兼容 Endpoint 必须是 `https://s3-<region>.qiniucs.com` 这种带 `s3-` 的格式，且**必须用 path-style**（应用已帮你处理，不用额外配）。另外**七牛的空间不能在应用里新建**，要先去七牛控制台建好桶，应用只做校验。
- **Q：又拍云为什么不用填 Endpoint / Region？** 又拍走自己的 REST API，不是 S3 协议。Endpoint 固定 `https://v0.api.upyun.com`（独立部署才改），也不分 region。凭据里的 **Operator 填在 AccessKey、Password 填在 SecretKey**。
- **Q：「复制外链」的链接过一会儿就打不开了？** 签名地址**默认 1 小时有效**，过期重新复制即可。要长期有效的直链，就把桶设成公开读（或挂 CDN 域名），再用 CMS 媒体库里那个**永久 URL**。
- **Q：改了密钥 / 换了桶，在哪确认生效？** 点 **健康检查 → 检查所有 provider** 逐家看 ✓ / ✗，再去 **CMS 媒体库** 传一张真图验证端到端。
- **Q：迁移跑到一半失败了几条怎么办？** 状态显示 `partial` 和失败数量。**迁移可以重复执行** —— 对着同一个源 Bucket 和 prefix 再点一次「开始迁移」，已经搬过的再做一遍是安全的（覆盖同名对象）。
- **Q：删文件后 CMS 的图片裂了？** 文件浏览里的删除是**直接删云存储对象**，删了就没。被页面引用的图，先在 CMS 里换成新图，再回来删旧的。
- **Q：关掉「保留本地备份」会怎样？** 之后的文件**只存云存储**，本机不再留副本，能省服务器硬盘。已存在的本地副本不会被自动清掉；但从此换云厂商要靠「迁移」功能，而不是靠本地备份。
- **Q：迁移期间能继续上传吗？** 能，但建议避开高峰期，也别在中途切换「当前激活」。

## 附：四家的 Region / Endpoint 怎么填

配置时输入框里会给提示，这里汇总一份方便对照：

| provider | Region 示例 | Endpoint 示例 |
|---|---|---|
| 腾讯云 COS | `ap-shanghai` / `ap-guangzhou` / `ap-beijing` | `https://cos.<region>.myqcloud.com` |
| 阿里云 OSS | `oss-cn-hangzhou` | `https://oss-<region>.aliyuncs.com` |
| 七牛云 Kodo | `z0` / `z1` / `z2` / `cn-east-2` | `https://s3-<region>.qiniucs.com` |
| 又拍云 | 不需要填 | `https://v0.api.upyun.com`（独立部署才改） |

**迁移任务状态**：`pending` / `running` 进行中、`done` 全部完成、`partial` 部分失败、`failed` 整体失败。
