# 内容采集 · 操作手册

## 这个应用解决什么问题

把外部网站 / RSS 订阅源的内容按规则抓进系统，进入「采集箱」，人工确认后一键转成 CMS 草稿。纯系统实现，不消耗 AI 额度。

典型场景：聚合行业资讯站、跟踪竞品动态、订阅技术博客。

## 从哪儿进

后台左侧菜单 **「内容采集」** 组：

- **采集规则**（配置抓什么、怎么抓）
- **采集箱**（抓回来的素材，处理入库）

需要权限：`collect:rule:read/write`（规则管理）、`collect:item:read/write`（采集箱）。

## 跑通一次的最短路径

1. 进「采集规则」→ 新建规则
2. 通道选 **网页（direct）**，填目标站列表页 URL（如 `https://example.com/news/`）；需要 JS 渲染的单页应用选 **JS 渲染页面**（browser）
3. 填 **链接选择器**（CSS）：如 `.news-list h2 a` —— 浏览器 F12 看列表标题链接的样式路径
4. 字段规则全部可视化点选，不用手写：
   - 「数据项」页签里给 `title` / `content` 等字段加卡片，点选提取方式（CSS 匹配 / XPath 匹配 / 正则匹配，可多选自动依次回退）；
   - 懒得配正文？直接用「自动提取兜底」快捷模板，引擎自动猜正文；
   - 每个字段还能追加**数据处理**（去除空白 / 正则替换 / 截取 / HTML 反转义 / 填充默认值等），点选即可；
   - 勾「匹配多条」可拼接多个节点（如全部标签），勾「不允许为空」试采集时空值会标红。
5. 选 **入库映射**（目标内容类型 / 分类）
6. 点 **试采集**：左侧出现链接样本 → 点一条看右侧字段提取预览和每步执行过程 → 不对就回来改
7. 预览满意 → 点 **采集**：新内容进入采集箱
8. 进「采集箱」→ 点标题预览全文 → 满意点 **转草稿**（或「更多 → 忽略」；也可先 AI 改写再转）
9. 转入的是**草稿**，带来源标注（原文链接/作者），去 CMS 内容管理里改稿后走正常审核发布

RSS 源更简单：通道选 RSS，填 feed 地址（如 `https://example.com/feed.xml`）即可，无需选择器。

## 日常操作速查

| 操作 | 说明 |
|---|---|
| 试采集 | 不落库，预览链接和字段提取效果（含每步执行过程），调规则用 |
| 采集 | 手动跑一轮，重复内容自动跳过 |
| 定时采集 | 规则里设「定时采集」分钟数，系统自动按间隔跑 |
| 转草稿 | 采集箱条目 → CMS 草稿（带来源标注，进正常审核流） |
| AI 改写 | 条目一键改写成原创（详见下文「AI 改写与发布」） |
| AI 聚合 | 勾选 2~8 条同主题素材，融合成一篇综述条目（详见下文） |
| 发布 | 改写过的条目直接发布上线（不经草稿审核） |
| 忽略 | 不想要的条目标记忽略，不再出现在待处理（支持批量） |

## 能抓到什么、抓不到什么（实话实说）

| 站点类型 | 结果 |
|---|---|
| 普通企业官网、行业资讯站、博客、SSR 社区 | ✅ 直接抓 |
| 需要 JS 渲染的单页应用（HTML 里没正文） | ✅ 选 **JS 渲染页面**通道（无头浏览器渲染后抓） |
| 强反爬平台（知乎/澎湃级别，403 拦截） | ❌ 抓不到，别浪费时间 |
| 要登录的页面 | ⏳ 可用「自定义请求头」带 Cookie 试，复杂的等 script 通道 |

JS 渲染通道说明：无头浏览器加载页面后再提取，「渲染等待」毫秒数可调（默认 1500ms，前端框架挂载慢的站调大）；并发上限 2，抓取速度比 direct 慢，只在该用的时候用。

抓不到时试采集会明确提示原因（403 / 空壳页 / 选择器没匹配），不会无限重试。

## 常见问题

**Q：抓回来正文带广告/导航？**
规则里加「剔除选择器」（如 `.ad-box`），一行一个。

**Q：列表页翻页怎么配？**
翻页模板填 `https://x/list_{page}.html`，页数设上限；或留空只抓第一页。

**Q：同一篇被两个源抓到会重复吗？**
不会，按 URL 归一化全局去重。

**Q：部署需要装依赖吗？**
需要。应用自带 `requirements.txt`（parsel / trafilatura / feedparser），在服务虚拟环境里执行 `pip install -r backend/src/apps/collect/requirements.txt` 后重启服务。

**Q：版权要注意什么？**
用「AI 改写」把素材消化成原创文章再发布；转出的草稿自带来源标注与 AI 溯源。目标内容类型为「新闻」时，转出/发布直接进入官网新闻（www.cenkor.cn/news.html 实时可见）；其他类型进入内容引擎草稿。

## 外链过滤与图片转存

采集来的内容自动做两件事，不需要配置：

**外链过滤（三道防线）**：
1. 入箱即清洗：正文里的超链接全部剔除（保留文字、保留图片），站名提一下、网址不留；
2. AI 改写时提示词明确禁止输出链接，改写结果再兜底清洗一遍；
3. 转草稿前最后再洗一遍——就算存量素材带链接，进 Entry 的正文也是干净的。

**图片转存**：转草稿时正文里的外站图片自动下载并转存到自有云存储（七牛），正文链接替换成自有 CDN 地址。好处：外站图挂了/防盗链也不会裂图，图片流量走自己的 CDN，图片统一进媒体库有总账。细节：
- 同一张图只转存一次（按 URL 缓存），重复转换零下载；
- 单图失败（404 / 超时 / 超 8MB）不影响整篇转草稿，保留原链接并计数（见条目来源信息里的 `images` 统计）；
- 已经是自有域名的图不重复处理。

## AI 改写与发布（全自动链路）

采集箱的条目不只是「原文搬运」，可以交给平台 AI 消化重写成原创文章再发布。

### 三步链路

1. **采集入箱**：规则跑一轮，素材进采集箱（状态：待处理）。
2. **AI 改写**：对待处理条目执行改写，AI 会——
   - 产出全新标题（不照抄原标题）+ 80 字内摘要 + 重新组织的正文（约 2500 字内）；
   - 忠于原素材的事实与观点，不编造素材里没有的内容；
   - 每次调用计入 AI 用量（AI 驾驶舱可见，类型 `collect_rewrite`）。
3. **转草稿 / 发布**：改写过的条目转草稿时自动采用 AI 版内容；转草稿时勾选发布则直接上线。

改写结果保存在条目上，重复改写覆盖上一次；详情抽屉里可对照「AI 改写稿 / 采集原文」双 Tab。
采集箱支持**批量**操作：勾选多条 → 批量 AI 改写 / 批量发布 / 批量忽略（并发执行，进度实时提示）。发布后的文章在 CMS 带 `ai_rewrite` 溯源
（所用模型、用量记录 ID），来源 URL 始终保留在 `custom_fields` 里可查。

### API 一览

| 端点 | 说明 |
|---|---|
| `POST /api/v1/collect/items/{id}/rewrite` | AI 改写单条（需 `collect:item:write` 权限） |
| `POST /api/v1/collect/items/aggregate` | AI 聚合，body 传 `item_ids`（2~8 条） |
| `POST /api/v1/collect/items/{id}/convert` | 转草稿；body 加 `"publish": true` 直接发布 |

### 前置条件与注意

- 后台「AI 设置」里 **chat 能力**已绑定服务商与模型；未配置时改写会明确提示，不影响采集与其他功能。
- 长素材（万字级）改写约需 20~60 秒，超时会提示重试；正文按「提炼成文」处理，不是全量复刻。
- 版权口径：AI 改写后内容已非原文，但来源标注系统会自动写入，请保留。

## 全自动发布（无人值守模式）

规则编辑 → 基本设置 → **自动处理** 三档：

| 档位 | 行为 |
|---|---|
| 不自动（默认） | 采集箱等人工处理 |
| 自动改写转草稿 | 采集到新内容 → 自动 AI 改写 → 转 CMS 草稿，进审核流 |
| 自动改写并发布 | 同上，但**直接发布上线**（无人审核，官网立即可见） |

配合「定时采集」使用：一条规则 = 无人值守内容工厂（定时抓 → 自动改写 → 自动发布，外链清洗与图片转存全程自动）。

须知：

- 自动管线每轮最多处理 **5 条**（AI 成本护栏），剩余的下一轮继续消化；
- 改写/发布失败的条目会标记原因并**跳过不重试**（防 AI 费用失控），后台采集箱可见失败原因；
- 自动档规则的所有待处理条目都会被自动消化——想人工把关某个源，就用「不自动」或「自动改写转草稿」档；
- 结果在规则列表「上次运行」统计里看：`auto: {processed, published, drafted, failed}`；
- **发布档请确认源站质量后再开**：内容直接对官网可见。

## AI 聚合（多篇融合一篇综述）

采集箱批量勾选 **2~8 条同主题素材** → 点「AI 聚合」→ AI 提炼共同主题，融合成一篇新条目：

- 产出新标题 + 摘要 + 4000 字内的论点式正文（3~5 个论点章节，真融合，不是逐篇拼接）；
- 素材间的观点冲突会客观并列呈现；不编造素材外的事实；不带任何链接；
- 结果落为一条新的**待处理**采集条目（原素材保留不动），可继续 AI 改写 / 编辑 / 转草稿 / 发布；
- 条目详情里可查溯源：融合自哪几篇素材、用的什么模型、用量记录 ID；
- 单次调用约 1~3 分钟，计入 AI 用量（类型 `collect_aggregate`）。

典型用法：一个热点事件从 3~4 个源各采一篇 → 聚合成一篇平衡的综述 → 改写定稿发布。
