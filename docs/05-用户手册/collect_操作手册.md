# 内容采集 · 操作手册

## 这个应用解决什么问题

把外部网站 / RSS 订阅源的内容按规则抓进系统，进入「采集箱」，人工确认后一键转成 CMS 草稿。纯系统实现，不消耗 AI 额度。

典型场景：聚合行业资讯站、跟踪竞品动态、订阅技术博客。

## 从哪儿进

后台左侧菜单 **「内容采集」** 组：

- **采集规则**（配置抓什么、怎么抓）
- **采集箱**（抓回来的素材，处理入库）

需要权限：`collect:rule:read/write`（规则管理）、`collect:item:read/write`（采集箱）。

## 跑通一次的最短路径

1. 进「采集规则」→ 新建规则
2. 通道选 **网页（direct）**，填目标站列表页 URL（如 `https://example.com/news/`）
3. 填 **链接选择器**（CSS）：如 `.news-list h2 a` —— 浏览器 F12 看列表标题链接的样式路径
4. 填字段规则：`title` 和 `content` 各一条（CSS 选择器 + 取 text / html）
   - 懒得配正文？留空也行，勾选「自动提取兜底」，引擎会自动猜正文
5. 选 **入库映射**（目标内容类型 / 分类）
6. 点 **试采集**：左侧出现链接样本 → 点一条看右侧字段提取预览 → 不对就回来改选择器
7. 预览满意 → 点 **采集**：新内容进入采集箱
8. 进「采集箱」→ 点标题预览全文 → 满意点 **转草稿**（或「忽略」）
9. 转入的是**草稿**，带来源标注（原文链接/作者），去 CMS 内容管理里改稿后走正常审核发布

RSS 源更简单：通道选 RSS，填 feed 地址（如 `https://example.com/feed.xml`）即可，无需选择器。

## 日常操作速查

| 操作 | 说明 |
|---|---|
| 试采集 | 不落库，预览链接和字段提取效果，调规则用 |
| 采集 | 手动跑一轮，重复内容自动跳过 |
| 定时采集 | 规则里设「定时采集」分钟数，系统自动按间隔跑 |
| 转草稿 | 采集箱条目 → CMS 草稿（带来源标注，进正常审核流） |
| 忽略 | 不想要的条目标记忽略，不再出现在待处理 |

## 能抓到什么、抓不到什么（实话实说）

| 站点类型 | 结果 |
|---|---|
| 普通企业官网、行业资讯站、博客、SSR 社区 | ✅ 直接抓 |
| 需要 JS 渲染的单页应用（HTML 里没正文） | ⏳ 暂不支持（browser 通道二期） |
| 强反爬平台（知乎/澎湃级别，403 拦截） | ❌ 抓不到，别浪费时间 |
| 要登录的页面 | ⏳ 可用「自定义请求头」带 Cookie 试，复杂的等 script 通道 |

抓不到时试采集会明确提示原因（403 / 空壳页 / 选择器没匹配），不会无限重试。

## 常见问题

**Q：抓回来正文带广告/导航？**
规则里加「剔除选择器」（如 `.ad-box`），一行一个。

**Q：列表页翻页怎么配？**
翻页模板填 `https://x/list_{page}.html`，页数设上限；或留空只抓第一页。

**Q：同一篇被两个源抓到会重复吗？**
不会，按 URL 归一化全局去重。

**Q：部署需要装依赖吗？**
需要。应用自带 `requirements.txt`（parsel / trafilatura / feedparser），在服务虚拟环境里执行 `pip install -r backend/src/apps/collect/requirements.txt` 后重启服务。

**Q：版权要注意什么？**
转入的草稿自带来源标注；发布前请改写整理，不要原文照搬直接发。
