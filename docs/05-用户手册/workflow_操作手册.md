# 工作流审批 · 操作手册

> **给谁看**：日常发起单据的人、要审批的人、负责画流程的管理员。
> 全文按**界面上实际点的位置**写 —— 每一步都说清「点哪里 → 看到什么 → 填什么」。
> 想改这个应用的代码看《二次开发指南》；想安装 / 升级看《部署方案》。

---

## 一、这个模块解决什么问题

公司里凡是需要「找人签字」的事 —— 请假、报销、采购、用章、合同 —— 都能放上来跑。
**不用写代码**：把流程在网页上画出来，系统就按画的走。

四类典型场景，配置方式各不相同：

| 场景 | 怎么配 |
|---|---|
| 请假单：直属上级批，人事备案 | 1 个审批节点（审批人＝上级）＋ 1 个抄送节点 |
| 报销单：5000 以内主管批，超过 5000 再加财务 | 条件分支：一条出线写 `amount <= 5000`，另一条留空兜底 |
| 合同：法务、财务同时审，都同意才过 | 并行节点；或把审批节点设为「会签」 |
| 大额单据要让总经理知道，但不用他批 | 抄送节点 |

和「把审批搬到线上」相关的两个前提概念，先记住：

- **表单**决定「单子上要填什么」（字段）；
- **流程**决定「谁先审、谁后审、什么条件走哪条线」（节点和连线）。
- 一个流程绑定一张表单；**两者都就绪并发布后，员工才能发起**。

## 二、从哪儿进

后台左侧菜单 → **工作流审批**（🔀），展开后共 11 项。按角色分三类：

### 所有人都会用到的 5 项

| 菜单 | 路径 | 干什么 |
|---|---|---|
| 📋 我的待办 | `/workflow/todo` | 等我拍板的单子。**每天第一眼就该看它** |
| 📤 我发起的 | `/workflow/mine` | 我提交过的，看进度、撤回、重新提交 |
| ✅ 我的已办 | `/workflow/done` | 我批过的历史 |
| 📨 抄送我的 | `/workflow/cc` | 抄给我看的，看完点「标记已读」 |
| 📖 使用教程 | `/workflow/help` | 就是这一页的操作手册，摆在菜单里随时能翻 |

### 流程管理员用的 5 项

| 菜单 | 路径 | 干什么 |
|---|---|---|
| 🧾 表单设计 | `/workflow/forms` | 建单据模板：这张单子填哪些字段 |
| 🧩 流程设计 | `/workflow/definitions` | 画流程：谁批、按什么顺序、条件分支 |
| 📊 流程监控 | `/workflow/monitor` | 在途单据统计；异常的单子可以中止 |
| 🔁 委托代理 | `/workflow/delegates` | 自己休假时把待办转给别人 |
| ⚙️ 工作流设置 | `/workflow/settings` | 配「谁的上级是谁」映射表 |

### 管理员额外 1 项

| 菜单 | 路径 | 干什么 |
|---|---|---|
| 📄 单据管理 | `/workflow/documents` | 全公司单据总入口：查询、代发起、导出、删除 |

> **看不到某个菜单 = 没有对应权限**，对着第七节《权限对照表》找管理员加。

## 三、三分钟跑通第一个流程

以「请假单」为例。走完这一节，套路就全掌握了。

### 第 1 步 · 建表单 —— 单子上要填什么

进入 **🧾 表单设计** → 右上角 **新建表单**：

1. 弹窗里填**表单名称**，例如「请假申请单」，确定；
2. 进入设计界面（左侧字段库、中间画布、右侧属性）；
3. 从左侧把字段**拖到中间画布**。目前支持的类型：

   | 类型 | 典型用途 |
   |---|---|
   | 文本 | 请假事由、备注 |
   | 数字 | 请假天数、报销金额 |

   也可以拖入**表格**来做明细行（例如报销的多个条目），表格的列同样只有文本、数字两种类型。

4. 选中某个字段，在右侧改两样东西：
   - **名称** —— 给人看的，如「请假天数」；
   - **标识（key）** —— 给流程条件用的，如 `days`；
   - ⚠️ **标识必须以字母或下划线开头，只能含字母、数字、下划线**。写中文或空格会被拦下并提示。
5. 保存。

> **这一步的产出**：一张请假单模板。单独还不能发起 —— 因为还没有流程。

### 第 2 步 · 画流程 —— 谁批、按什么顺序批

进入 **🧩 流程设计** → **新建流程**：

1. 弹窗里填**流程名称**（如「请假审批」），选**关联表单**（上一步建的「请假申请单」）；
2. 点 **创建并设计** 进设计器。画布上已默认摆好三块：**开始 → 审批 → 结束**；
3. 点中间那个**审批节点**，右侧属性面板从上往下配：

   | 属性 | 说明 |
   |---|---|
   | 节点名称 | 会显示在待办里，写具体些，如「直属上级审批」 |
   | **审批人** | 6 种方式，见下表 |
   | **审批模式** | **或签**＝一人同意即可（默认）；**会签**＝全部人都要同意 |
   | 允许驳回 | 勾上，审批人才能打回 |
   | 允许转办 | 勾上，审批人才能转给别人 |

   **审批人的 6 种指定方式**，按常用度排：

   | 方式 | 什么时候用 |
   |---|---|
   | **上级** | 最常见的场景。读「工作流设置」里的上级映射表。⚠️ **没配映射时这个节点会自动通过**（不卡人），所以上线前务必先把映射表填好 |
   | **指定人员** | 固定几个人审，如「总经理」 |
   | **按角色** | 谁有这个角色谁审，如「财务」角色下的所有人 |
   | **发起人本人** | 自己审自己（确认类流程） |
   | **表单字段值** | 审批人由单据内容决定 —— 表单里放一个「指定审批人」字段，填写人自己选 |
   | **提交时勾选** | 发起人提交那一刻才选审批人，适合临时决定 |

   > ⚠️ **默认是「发起人本人」**。新建流程后如果你不点开改，等于自己批自己 —— 这是最容易踩的坑。

4. 从右侧节点库拖入其他节点就能扩展流程：

   | 节点 | 用途 |
   |---|---|
   | **条件分支** | 按条件走不同的路 |
   | **并行** | 几条线同时走 |
   | **抄送节点** | 只是知会，不需要批 |

5. 画完点 **校验**，有问题会列出来（例如忘了把某条线连到结束节点）。

### 第 3 步 · 发布

| 按钮 | 效果 |
|---|---|
| **保存** | 存成草稿，**还不能用** |
| **保存并发布** / **发布** | 真上线，员工才能发起 |

发布后还能改：点 **转草稿** → 改 → 再点 **发布**。
想暂时下线用 **停用**（**已发起的单子不受影响**，会照常走完）。

> ⚠️ **只有「已发布」的流程能被发起**。如果有人说「找不到这个流程」，先回这里看状态。

### 第 4 步 · 发起一张单

进入 **📤 我发起的**（或 **📄 单据管理**）→ **发起申请**：

1. 选流程（只列出已发布的）；
2. 弹出表单，按字段填；
3. 若流程里有「提交时勾选」的节点，这一步会让你选审批人；
4. 提交。

提交后单据状态变为 **审批中**，对应审批人的「我的待办」里会立刻多一条。

### 第 5 步 · 审批

让审批人登录（或换个账号）→ **📋 我的待办** → 找到那条 → **处理**。

抽屉里能看到：**单据内容**、**流程图当前走到哪**、**之前的审批记录**。底部四个动作：

| 动作 | 效果 |
|---|---|
| **同意** | 通过，流程往后走 |
| **驳回** | 打回给发起人，发起人可修改后**重新提交** |
| **转办** | 我不批了，转给指定的人 |
| **加签** | 我觉得还需要别人一起看，临时加一个审批人 |

四个动作都支持填写**审批意见**。

到这里，一个完整闭环就跑通了：**建表单 → 画流程 → 发布 → 发起 → 审批**。

## 四、日常操作速查

### 我的待办

- **刷新** —— 手动拉最新（页面不会自动刷新）
- **处理** —— 打开审批抽屉，做同意 / 驳回 / 转办 / 加签

> 或签流程里，只要有一个人同意，其他人的待办会自动变成「已跳过」，不用管。

### 我发起的

- **详情** —— 看走到哪一步了、每个人批了什么意见
- **发起申请** —— 再发一张新的
- **撤回** —— 审批中不想走了，撤回（撤回后状态是「已撤回」）
- **重新提交** —— 被驳回后改完再提交

### 我的已办

查历史。点**详情**看当时的审批意见。

### 抄送我的

抄送来的单据，看完点**标记已读**。这个只是通知，不需要任何操作，也不影响流程。

### 委托代理

要休假、出差，怕耽误别人审批时用：

1. **新建委托** → 选**受托人**和**生效时间范围**；
2. 期间本该到我这里的待办，会自动转给受托人；
3. 回来后可以**删除**这条委托。

## 五、把流程画得更聪明

### 条件分支：表达式写在「连线」上

这是个和其他系统不太一样的地方 —— **条件不写在节点上，写在连线上**：

1. 从条件分支节点拖出多条线，连到不同节点；
2. 点**连线**，右侧出现「条件表达式」输入框；
3. 写法就是普通判断，字段名用表单字段的**标识（key）**：

   ```
   amount <= 5000
   ```

   ```
   amount > 5000 and type == "travel"
   ```

   ```
   days >= 3
   ```

4. **最后一条线留空当作兜底**（无条件），保证任何情况都能走通。

⚠️ 两条容易踩的规则：

- **从上往下取第一条成立的线** —— 所以顺序很重要，把「范围窄」的条件放上面，兜底放最下面；
- 连线的**顺序决定了判断顺序**，不是同时判断。

### 并行：几条线同时走

并行节点的所有出线会**同时推进**，而且是**会签式**的 —— 每条分支都走完，流程才继续往下。

用在哪：法务、财务、技术三个部门同时会审，谁都别等谁。

### 会签 / 或签 怎么选

| 模式 | 行为 | 典型场景 |
|---|---|---|
| **或签**（`any`） | 其中**一人**同意就过，其余人的待办自动变成「已跳过」 | 同岗位有多个备用审批人时 |
| **会签**（`all`） | **所有人**都同意才过 | 需要多部门共同负责时 |

**审批人数多、但只要是"他们中随便一个"就行 → 用或签**（否则会集体卡住）。

### 上级映射表怎么配

用「上级」作为审批人时，系统要去一张表里查「谁的上级是谁」：

1. 进入 **⚙️ 工作流设置**；
2. 在「上级映射」里 **添加** 一行：左边选**员工**，右边选他的**上级**；
3. 保存。

> ⚠️ **没配置映射的人，流程里「上级」节点会直接自动通过** —— 不会报错、不会卡住。
> 这个设计是为了不让流程走不下去，但也意味着**配漏了不会有任何提示**。
> 上线前建议专门核对一遍。

## 六、管理员操作

### 流程监控

看两样东西：

- **统计** —— 有多少单子在跑、多少已完成、多少被驳回；
- **在途列表** —— 当前正在走的单据；

对卡住的单子点 **中止** 可以强行终止。

> 什么时候用：某单子因为审批人离职、组织调整而卡住，或者发起人填错了又撤不回。

### 单据管理

全公司单据的总入口，比「我发起的」多了：

| 操作 | 说明 |
|---|---|
| 按条件**查询** | 全量单据检索（不限于自己） |
| **发起申请** | 代某人发起 |
| **导出** | 把单据内容导出成文本 |
| **删除** | 彻底删除单据记录（谨慎使用） |

### 流程设计 / 表单设计

除了上面讲过的建和改，还需要知道一个约束：

> ⚠️ **已经被单据使用的表单 / 流程，不要随意删除**。要下线请用**停用**，删除会破坏历史单据的展示。

## 七、权限对照表

普通员工**不需要任何额外权限**，只有做管理和审批动作才需要：

| 功能 | 需要的权限码 |
|---|---|
| 我的待办 / 已办 / 我发起的 / 抄送我的 | 登录即可 |
| 撤回、重新提交自己的单子 | 登录即可 |
| 委托代理 | 登录即可 |
| **同意 / 驳回 / 加签** | `workflow:task:approve` |
| **转办** | `workflow:task:transfer` |
| 查看流程、表单 | `workflow:definition:read`、`workflow:form:read` |
| 新建 / 修改流程、表单 | `workflow:definition:write`、`workflow:form:write` |
| **发布 / 停用 / 转草稿** | `workflow:definition:publish` |
| 删除流程、表单 | `workflow:definition:delete`、`workflow:form:delete` |
| 单据管理（全量查询、代发起） | `workflow:document:read` / `write` |
| 导出单据 | `workflow:document:export` |
| 删除单据 | `workflow:document:delete` |
| 流程监控 | `workflow:monitor:read` |
| 改工作流设置（上级映射） | `workflow:admin` |

> 最省事的分配方式：给**普通员工**不加权限（开箱即用）；
> 给**部门主管**加 `workflow:task:approve` + `workflow:task:transfer`；
> 给**流程管理员**加全部 `workflow:*`。

## 八、常见问题

**Q：菜单里看不到「工作流审批」？**
没有该应用的访问权限 —— 找管理员在角色里挂上对应权限，权限是实时生效的，不用重新登录。

**Q：发起时找不到我要的流程？**
那个流程还是**草稿**或**已停用**。让流程管理员去 **流程设计** 里点 **发布**。

**Q：提交了，但审批人的待办里没有？**
按顺序排查：① 流程是否已发布；② 审批人配的是「上级」吗 —— 那样要看**上级映射表有没有配**（没配会直接自动通过，单据会一路走完，所以你看到的是"没人审就过了"）；③ 让审批人点一下 **刷新**（页面不自动刷新）。

**Q：审批人说同意/驳回按钮点不了？**
缺 `workflow:task:approve` 权限。转办按钮点不了是缺 `workflow:task:transfer`。

**Q：条件分支配了却没生效，总是走同一条？**
两个常见原因：① 表达式里的字段名用了**显示名称**而不是**标识（key）** —— 必须用标识；② 顺序问题，系统**从上往下取第一条成立的**，把窄条件放上面、兜底留空放最后。

**Q：并行节点为什么一直不往下走？**
并行是**会签式**的 —— 每条分支都得走完。多半是某条分支上的审批人还没处理，去 **流程监控 → 在途列表** 看卡在哪个节点。

**Q：想改一个已经在用的流程，会影响正在审批中的单子吗？**
不影响。**已发起的单据按发起时的流程走完**，改动只对之后新发起的单据生效。

**Q：单子发错了能撤吗？**
可以，在 **我发起的** 里点 **撤回**。如果已经批完了，找管理员在 **流程监控** 里 **中止**。

**Q：被驳回了怎么办？**
在 **我发起的** 里点 **重新提交**，改完再走一遍；也可能需要**撤回**后重新发起。

## 附：单据状态都代表什么

| 状态 | 含义 |
|---|---|
| 草稿 | 建了还没提交 |
| 审批中 | 正在流转，等审批人处理 |
| 已通过 | 全部审批节点通过 |
| 已驳回 | 被某个审批人打回 |
| 已撤回 | 发起人自己撤回的 |

**单个审批任务**的状态：待处理 / 已同意 / 已驳回 / **已跳过**（或签模式下别人先同意了）。
