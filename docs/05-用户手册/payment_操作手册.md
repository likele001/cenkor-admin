# 支付中心 · 操作手册

> **给谁看**：负责开通收款、盯流水、给客户退款的人（一般是财务或运营）。
> 全文按**界面上实际点的位置**写：点哪里 → 页面上做什么 → 系统会发生什么。
> 这是**配置型**模块：配好通道就是 90% 的工作，剩下是查单和退款。

---

## 一、这个模块解决什么问题

让平台上的业务应用能**收钱**：电商下单、会员充值、SaaS 续费 —— 业务应用调一下支付中心，就能拉起微信 / 支付宝付款，收完还会自动回调业务侧。三件事：

1. **配通道** —— 决定用哪家收款（支付宝官方 / 微信官方 / 虎皮椒聚合），填哪家的商户号和密钥；
2. **看订单** —— 谁在什么时候付了多少、成没成、回调到了没；
3. **退款 / 对账** —— 原路退钱、按网关同步状态、翻回调日志找差错。

必须先记住一个概念：**业务场景（scene）**。

> 平台的每个应用（如 CMS、CRM、商城、应用中心）都算一个「业务场景」。
> **每个场景各有各的通道配置和各自的流水**，互不影响 —— 同一套微信商户号可以给 A 应用用，B 应用另配一套。
> 查订单时第一件事永远是：**先选场景**，否则看到的是别的应用的账。

## 二、从哪儿进

后台左侧菜单 → **支付中心**（💳），只有两项：

| 菜单 | 路径 | 干什么 |
|---|---|---|
| 🔌 支付通道 | `/payment/channels` | 配谁来收款：新增 / 编辑 / 启停 / 设为默认 / 连通性检测 |
| 🧾 支付订单 | `/payment/orders` | 各场景的收款流水：查询、详情、同步、关闭、退款 |

页面上方通常带一个**场景切换**，通道和订单都跟着它走。**看不到菜单 = 没有权限**，查第七节。

## 三、十分钟配好一条通道

以「给商城接微信支付」为例，别的通道照抄。

**第 1 步 · 认一下三家通道。** 点 **🔌 支付通道** → **新增支付通道**，「通道类型」下拉里就三个：

| 通道类型 | 显示名称 | 支付方式可选 | 适合 |
|---|---|---|---|
| `wechat` | 微信支付（官方） | 无（就是微信） | 有微信商户号，走官方直连 |
| `alipay` | 支付宝（官方） | 无（就是支付宝） | 有支付宝开放平台应用 |
| `xunhupay` | 虎皮椒 / 讯虎（第三方聚合） | **微信支付 / 支付宝** | 个人或小微企业，一个账号同时收微信和支付宝 |

**第 2 步 · 填参数。** 表单每项都标了必填 / 选填：

**① 微信支付（官方）** —— **AppID**✅（公众号 / 小程序 / APP 的 appid）、**商户号**✅、**APIv3 密钥**✅（32 位字符串，**必须与商户平台一致**，回调靠它解密）、**商户证书序列号**✅（16 进制串）、**商户私钥**✅（`apiclient_key.pem` 的内容）、**平台证书**（选填，填了回调会额外验签，**更安全，建议填**）。

**② 支付宝（官方）** —— **应用 AppID**✅、**应用私钥**✅、**支付宝公钥**✅、**网关地址**（选填，留空按环境自动选）、**签名算法**（选填，默认 **RSA2**）、**校验响应签名**（选填，默认**开**，生产建议保持开启）。

**③ 虎皮椒 / 讯虎（第三方聚合）** —— **AppID**✅、**AppSecret**✅、**接口地址**（选填，讯虎独立部署才填自己的域名）、**收单方式**（选填，留空**自动**；也可指定 **NATIVE（PC 扫码）/ WAP（支付宝手机网站）/ MOBILE（微信 H5）/ WECHAT（微信内 JSAPI）**）。

**第 3 步 · 补齐通道属性。** 同一个弹窗里还有：

| 字段 | 说明 |
|---|---|
| **业务场景** | 这条通道服务哪个应用。下拉里能选到已安装的应用、已有场景，以及内置的「应用中心」「默认场景」；也能手动输入场景标识（建议小写字母，如 `shop`） |
| **支付方式** | 只有虎皮椒有：微信 / 支付宝。一个账号要同时收两种，就**建两条通道**各选一种 |
| **标题** | 列表里显示的名字，留空用通道类型的显示名 |
| **运行环境** | **生产环境（live）** 或 **沙箱环境** |
| **启用** | 关掉即停用，下单不会走到它 |
| **设为该场景默认通道** | 见下方说明 |
| **排序 / 备注** | 排序数字越小越优先；备注给自己看 |

> ⚠️ **每个场景同时只能有一条默认通道** —— 勾了新的，系统自动取消原来的。下单时优先走「默认通道」，调用方也可显式指定用哪条。

保存后列表里出现这条通道，并提示 **通道已创建**。

**第 4 步 · 连通性检测。** 在这条通道上点 **连通性检测** —— 系统拿一个**不存在的单号**去问第三方：

| 结果 | 含义 |
|---|---|
| ✅ 检测通过：**配置可用（签名与网络均正常）** | 密钥、签名、网络都通了 |
| ❌ 检测失败 | 下面给具体原因（密钥不对 / 网络不通等），照着改 |

> 通过只代表「签名和网络没问题」，**不代表客户真能付钱** —— 上线前务必用真订单走一遍小额支付。

**第 5 步 · 上线。** 确认 **启用** 是开的、这个场景的 **默认通道** 是它 → 让业务应用下一单试试 → 回 **🧾 支付订单** 看状态是否变 **已支付**。

## 四、日常操作速查

### 支付通道

| 动作 | 说明 |
|---|---|
| **新增支付通道** | 见上一节 |
| **编辑** | 改标题、场景、运行环境、参数、排序、备注。⚠️ 密钥显示成 `****`，**留空就是不改**，要换才重填（密钥一律加密存储，界面只显示掩码） |
| **启用 / 停用** | 一键切，停用后新订单不会走它，**已有订单不受影响** |
| **设为默认** | 把这条设为当前场景的默认通道 |
| **连通性检测** | 见上 |
| **删除** | ⚠️ 二次确认「该操作不可撤销」。删除只是停止使用，历史订单仍在 |

### 支付订单

顶部先 **选场景**，再按条件查：

| 筛选项 | 说明 |
|---|---|
| **场景** | 全部场景 / 指定应用 |
| **状态** | 全部状态 / 待支付 / 已支付 / 已关闭 / 支付失败 / 已退款 / 部分退款 |
| **通道** | 按通道类型筛 |
| **关键词** | 订单号 / 第三方支付单号 / 标题 |
| **时间范围** | 下单时间起止 |

列表列：订单号、场景、通道、标题、金额（元）、已退款、状态、业务单号、来源 IP、创建时间、支付时间、回调次数。

**订单详情**（点 **详情**）里能看到：**订单信息**（订单号、第三方单号、金额、状态、业务类型 / 业务单号、支付时间）、**退款记录**（退过几次、退了多少、退款单号、原因、状态）、**回调日志**（回调时刻、**验签**通过没通过、**已处理**、来源 IP、出错信息）。

三个操作：

| 操作 | 什么时候用 | 效果 |
|---|---|---|
| **与网关同步** | 客户说付了、订单还是「待支付」（回调丢了） | 主动去第三方查一次，查实已付款就置为**已支付**，并补发业务通知 |
| **关闭订单** | 挂着的单不想让它再被支付 | ⚠️ **只有「待支付」能关**，关掉是终态（不能重开），用户无法继续支付，状态变 **已关闭**；要让客户再付只能重新下单 |
| **发起退款** | 客户要退钱 | 见下 |

### 退款怎么操作

在订单详情里点 **发起退款**：① 填 **退款金额（元）** —— 页面提示 **「最多可退 X」**（＝订单金额 − 已退金额），填超了会被拦下提示 **退款金额超出可退额度**；② 填 **退款原因**（选填，会同步给渠道）；③ 确认 → 提示 **退款已提交并受理**。

之后：钱**原路退回**，到账时间取决于渠道（**一般即时，银行卡可能 1 个工作日**）；全退 → 订单变 **已退款**，只退一部分 → **部分退款**；退款单自身有状态（成功 / 失败）和**退款单号**，在「退款记录」里查；退款失败会直接报错（如渠道额度不足），**不会**把订单改成已退。

**看经营数据。** 概览里有 **订单总数、已支付订单、今日交易额、累计交易额**，以及**按状态**、**按通道**的分布 —— 做日报 / 对账的第一眼判断。

## 五、进阶

**回调与对账。** 客户付完钱，第三方**回调**支付中心，中心验签后把订单置为已支付，再**通知业务应用**（告诉它哪笔业务单付好了）。每次回调留一条**回调日志**并记**回调次数**；第三方没收到明确应答会**重复回调**，中心是幂等的，已支付的不会重复入账。对账标准动作：① 筛某天的订单；② 找出状态不是「已支付」但客户说付了的；③ 点 **与网关同步**；④ 还不对，就看该单的**回调日志**和**验签**字段 —— 验签总不过，八成是密钥 / 平台证书配错了。

**收银台。** 下单后系统给一个**收银台链接**，客户在这个页面完成付款、也能查这笔单的状态。页面是公开的（不需要登录），可以直接发给客户。

## 六、管理员设置

| 事务 | 在哪 | 权限 |
|---|---|---|
| 新增 / 编辑 / 删除通道、启停、设默认、连通性检测 | 支付通道 | `payment:write` |
| 同步订单、关闭订单、发起退款 | 支付订单 → 详情 | `payment:write` |
| 查订单、看退款记录、看回调日志、看统计 | 支付订单 | `payment:read` |

⚠️ **收口建议**：能改通道配置（也就是能看到商户密钥）的人，权限比只能查单退款的人高得多。财务一般只给 `payment:read`，`payment:write` 留给技术负责人。

## 七、权限对照表

支付中心的权限点只有两个：

| 权限 | 能做什么 |
|---|---|
| `payment:read` | 看通道列表与详情（密钥是掩码）、查订单 / 退款记录 / 回调日志、看统计概览 |
| `payment:write` | 新增 / 编辑 / 删除 / 启停通道、设默认、连通性检测、与网关同步、关闭订单、发起退款 |

> **场景可选清单**来自「已安装的应用」+「已有通道的场景」+ 内置的「应用中心」「默认场景」—— 要让某个应用出现在场景下拉里，它得先是**已安装**状态。

**建议分法**：**财务 / 客服** 只给 `payment:read`（能查单、看日志，不能改配置、不能退款）；**收款负责人** 给 `payment:read` + `payment:write`。退款是**资金动作**，建议只给到具体某个人，不要按角色大范围发。

## 八、常见问题

- **Q：新增通道提示「缺少必填配置：XXX」？** 就是那个参数没填，对着第三节的表格核对。密钥类字段粘贴时容易多带换行 / 空格，注意。
- **Q：编辑通道时密钥框是 `****`，要不要重填？** 不用。**留空或保持原样就是不改**，只有真要换密钥时才重新粘。
- **Q：怎么判断通道配没配对？** 点 **连通性检测**，通过会说「配置可用（签名与网络均正常）」。但这只验证了签名和网络，**上线前必须用真实小额订单验证一次完整支付**。
- **Q：客户付了钱，订单还显示「待支付」？** 按顺序：① 订单详情点 **与网关同步**（最常见就是回调丢了，同步一下就回来）；② 还不行看 **回调日志** —— 没有日志说明第三方没回调到你的地址（域名、回调地址、防火墙）；有日志但 **验签** 不过，是密钥 / 平台证书配错。
- **Q：同一场景配了好几条通道，走哪条？** 优先走**默认通道**；下单方也可明确指定。下单时只有**启用**的通道才会被选中。
- **Q：想把某场景的收款换一家，怎么切最稳？** 先把新通道配好、测通 → 把新通道 **设为默认** → 让业务侧下一单验证 → 最后停用旧通道。⚠️ **别先删旧的**，已发起的订单还要靠它查状态和退款。
- **Q：退款提交了，客户说没收到钱？** 成功与否看订单详情的「退款记录」。渠道到账：微信 / 支付宝一般即时，**银行卡可能 1 个工作日**；超时未到，凭**退款单号**去渠道商户后台查。
- **Q：虎皮椒想同时收微信和支付宝？** 建**两条**通道：通道类型都选虎皮椒，**支付方式**一条微信、一条支付宝，其余参数一样；哪个是默认就决定默认收款方式。
